### 0.2 四类分析状态与教师复核

| 原始状态 | 主界面文字 | 图标 | 前景 / 浅背景 |
| --- | --- | --- | --- |
| `candidate`，未撤销 | 发现疑似问题 | 圆角三角警示＋叹号 | `#92400E` / `#FFF7ED` |
| `not_observed` | 已检查未发现问题 | 圆圈＋对勾 | `#166534` / `#F0FDF4` |
| `unable` | 暂无法判断 | 圆圈＋问号 | `#475569` / `#F1F5F9` |
| `pending_rule` | 需教师判断 | 剪贴板＋人工复核标记 | `#1D4ED8` / `#EFF6FF` |

- `review=confirmed` 是原候选问题的复核标记，显示「教师已确认」，不是第五种算法状态，不额外增加总条目数。
- `review=revoked` 的候选项从当前问题数和默认问题列表移出，单独显示「教师已撤销 N 项」并可展开；不能计入未发现问题。
- 四类数量＋已撤销数量应与原始检查项总数一致，候选项以 `check.id` 去重；问题分组不改变检查数量。未确认＋已确认＝当前未撤销候选问题数。
- 若全部可自动检查项均为 `unable`，主标题显示「本次未能完成有效判断」；不能因候选问题为0显示合格。只有待人工项目时显示「本次需教师判断」；取消/失败另作任务状态。
- 部分可判断时显示「分析完成，部分项目暂无法判断」；零候选且存在待确认项时显示「已检查项目未发现问题，仍有待判断项目」。
- 不显示总分、扣分、合格率、准确率，也不把问题支持度画成评分进度条。

## 1. 目标体验与边界

目标：用户在分析完成后的首屏能看出“哪里需要关注、属于哪个动作阶段、点哪里看依据”，不必导出TXT再阅读。用户目前使用旧版 Tk 桌面，因此第一版接入 `apps/app_ui.py`，不迁移到 Vue/Tauri。

实现结果：

1. 学生模式主内容区增加「录制预览 / 分析结果」切换；复用当前主窗口，结果页不能仍塞进左侧小文本框，也不每次弹新窗口。
2. 结果已保存且仍属于当前任务/学生后，自动切到分析结果；允许切回预览，旧历史打开同一个结果视图。
3. 首屏提供概览、状态分类、阶段导航、问题列表与正侧证据区；技术信息默认折叠。
4. 新增单文件离线 `.html` 图文报告；保留原 `.txt` 详细报告。页面与导出使用相同状态、数量和排序。
5. 不改变MediaPipe模型选择、分段算法、权重、阈值、规则、教师复核权限/契约与14天保留规则。单纯改展示不升级 `ruleVersion` 或伪造新分析；需要时单独定义展示版本。
6. PDF直接导出、视频播放器、自动训练建议、云端分享、完整历史页面重构均不在首版范围。导出HTML预留打印排版，不宣称已有PDF按钮。

## 3. 页面信息与交互规范

### 3.1 首屏

- 头部：学生学号/姓名、动作/左右式、分析时间与当前记录标识。日期显示本机时间并明确时区/偏移，保留原始UTC记录，不截断UTC字符串冒充本地时间。
- 概览：四类状态计数与独立的撤销计数；数量都是检查项目数，不是动作错误次数。概览状态可用文字及少量图标，不做四个巨大数字卡。
- 阶段：根据记录中真实阶段生成，选中后筛选列表；选择项同时显示完整段名/检查名，避免只有缩写。
- 左侧：默认优先候选问题，包含教师已确认标签；状态分类可切换。无候选时自动展示无法判断的原因或待人工项目，不留空白列表。
- 右侧：选中检查的正面/侧面代表帧和一句依据。下一层才展开标准、测量值、视角适用性与来源。
- 操作：再练一次（仅返回录制页，不直接启动摄像头/录制）、个人历史、导出图文报告；技术诊断以「分析依据」折叠区保留。

### 3.2 “杂乱”具体如何消除

- 主结论一句话，基于已有检查名/动作/部位生成，不新增模型，不编造纠正动作建议。
- 同原因影响多项时允许展示“同一原因影响N项”，展开能看到原始每项。以明确原因类别、机位和必要阶段为键；无结构化类别时只合并同视角同阶段的完全相同原因，不用模糊相似度合并不同事实。
- 规则待确认、不可测厘米、缺画面等保持不同类别，不能统一合成“动作错误”。
- 分辨率、文件标称FPS、关键点比例、对齐残差、基础/实际权重、支持度放分析依据，不挤在问题清单前。
- 算法状态、教师复核、运行失败是三个不同概念，颜色不能互相覆盖含义。

### 3.3 自动展示与记录绑定

- 新分析、导入视频和重新分析成功保存后，都复用同一个结果展示入口；不增加用户每次勾选的开关，默认自动展示。
- 复用当前worker→queue→Tk `after`回调；所有Tk控件及PhotoImage创建/更新必须在主线程，视频读取/缩略图处理不长期阻塞界面。
- 绑定本次 `record.id`、`revision`、学生及任务代次；切学生、再练、关闭、取消或新任务后到达的旧图像/结果不能覆盖新页或强制跳回。先检查现有锁定行为，只有当前机制不足才加最小代次标记。
- 分析失败/取消保留原历史结果但明确标出“这是上次结果”，不得伪装本次完成；取消不得创建新历史。
- 教师确认/撤销后从存储获取新revision，立即刷新可见详情、概览及下一次导出。
- 老记录字段缺失时显示“旧版记录未提供此信息”，支持无diagnostics、measurements、landmarks的已存记录；仅为显示不得自动重跑分析。

### 3.4 证据帧

- 复用当前证据ID→视频副本→frame定位；检查文件仍在当前受管记录目录内且不是越界链接。原视频不存在、过期或解码失败时显示明确占位，其他文字结果仍可查看/导出。
- 首先显示当前选中项每路1张代表帧，再可切换其余已有证据（当前每路最多3张）；不用预解码整段录像或全部检查项图片。证据少于预期时如实显示。
- 骨架坐标转换沿用当前高度归一化约定，不能把x误乘图像宽度；只绘制validMask有效且参与该项检查的点/连线，不补全被遮挡的肢体。
- 保留未标注原图可查看。时间各自取真实 `timeSeconds`，正侧帧未必同一瞬间；标注真实时间，禁止把“各路代表帧”写成“精确同步帧”。共享阶段来源/单视角公式限制可在依据中查看。
- 旧记录没有骨架时只显示原帧及“无关键点标注”，不为了画图重新推理。图标/缩略图缓存有界，切换/关闭释放引用。

## 4. 导出图文报告规范

1. 导出为一个可复制到其他电脑的 `.html` 文件，UTF-8，本地字体，内嵌CSS/SVG图标和JPEG/PNG data URI证据图片。无CDN、远程字体、外链图片、联网请求或本地服务；第一版可零JavaScript。
2. 内容顺序：身份与动作→一句总览→各类数量→问题及证据→无法判断/教师判断→已检查未发现→折叠分析依据。正文所有检查条目都可访问；不因桌面当前筛选而漏导出。
3. 已撤销项单列，教师确认信息来自当前revision；导出头部记录生成时间与结果版本，属于当时快照。
4. 默认为候选问题嵌入每路最多一张代表图；缺证据/非问题项保留文字依据，不给每条都铺六张图。相同证据去重，限制缩略图尺寸、单图压缩及总体数量，达到上限明确说明省略图片但不省略检查条目。
5. 学生姓名、教师姓名、备注、标准、原因等统一进行HTML转义；不得将历史字段当HTML或脚本拼接。SVG图标为受信本地静态资产。
6. 保留现有TXT导出，可在同一导出对话框选择“图文报告HTML / 详细文字TXT”；HTML为默认。导出取消不写文件，写入失败不损坏已有文件。延用受管目录/原视频保护和原子替换，重名覆盖由保存对话框正常确认。
7. 图片从当前记录安全目录解析；报告不包含用户机器绝对路径、调试堆栈或源录像路径。导出的图文报告包含学生和证据，保存对话框旁简短注明这一点即可。
8. 页面采用可打印排版（A4边距、黑白下仍能读懂状态、问题和图片尽量不跨页）；打印时展开必要内容并隐藏交互按钮。PDF正式导出不属本轮。
9. 导出照片和结论保存在用户选择的位置，是独立快照；不自动加入14天清理。现有历史/原录像保留规则不变。

## 6. 最小验证与验收表

| 场景 | 必须满足 |
| --- | --- |
