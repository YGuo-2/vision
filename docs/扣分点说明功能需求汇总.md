# 扣分点说明功能需求汇总

来源：甲方填写的《扣分点说明功能需求问卷(1).docx》。

本文仅归纳甲方已勾选、填写的内容。空白项不视为已确认需求，未勾选项不直接视为明确排除；相互矛盾的填写单独列出。问卷中的动作标准是甲方提供的规则输入，不代表已完成技术可行性验证或形成验收承诺。

## 1. 需求目标

现有系统只展示最终得分，拟增加动作问题说明，主要用于学生练习后了解自身问题，以及教师讲解、纠正动作。

- 主要使用者：学生。
- 优先场景：教室。
- 首期方向：文字指出动作不规范之处。
- 甲方在附表中明确填写“第一版不打分”。本汇总据此不将逐项扣分计算纳入已确认需求；是否保留、调整现有总分，仍需明确。
- 判定依据：指定教师确认的规则。
- 适用标准：所有人使用同一标准。

## 2. 首期动作范围

以下动作均填写为“本期必须”。

| 动作 | 变体 | 动作形式 | 已填写的补充信息 |
| --- | --- | --- | --- |
| 实战式 | 未填写 | 单次动作 | 各专项规则中均包含开始与结束时的实战式检查 |
| 直拳 | 前后手 | 组合动作 | 组合顺序填写为“前后顺序” |
| 摆拳 | 前后手 | 组合动作 | 组合顺序填写为“前后顺序” |
| 低鞭腿 | 前后脚 | 单次动作 | 分别提供前低鞭腿、后低鞭腿规则 |

“前后顺序”尚不足以确定完整动作序列、次数，以及漏做、顺序错误或次数不足的处理方式。

## 3. 甲方提供的动作问题清单

以下归并了问卷中重复出现的规则。甲方在相关规则表中标注“必须识别”；是否能识别及验收指标尚未约定。动作标准中还描述了转体、蹬地等技术要求，但未全部列为独立错误项，本文不自行扩展。

### 3.1 实战式

适用于开始（第一步）和结束（最后一步）。

| 检查项 | 甲方填写的动作标准 | 需要指出的问题 |
| --- | --- | --- |
| 前手角度与高度 | 两手握拳、双肘向下；前手大小臂夹角90°～135°，拳峰与鼻尖同高，允许差值±3 cm | 前手角度不在范围内；拳峰高于或低于要求位置 |
| 后手护位 | 后手大小臂夹紧，紧贴肋骨与下颚 | 未夹紧，未紧贴肋骨与下颚 |
| 屈膝 | 两膝微屈 | 单腿或双腿伸直 |
| 站距 | 两脚略与肩同宽，允许差值±10 cm | 两脚过宽或过窄 |
| 脚尖方向 | 两脚大致平行，朝斜前方 | 两脚内八或外八 |
| 躯干朝向 | 躯干侧向前方 | 躯干正向前方 |
| 头部与胸腹姿态 | 下颚微收、含胸收腹 | 挺胸抬头 |

上述角度、距离来自问卷填写，测量基准、边界容差与适用拍摄条件尚未说明。

### 3.3 摆拳

| 动作 | 需要指出的问题 | 观察阶段 |
| --- | --- | --- |
| 前手摆拳 | 后手向下掉手、向后拉手、向上抬肘 | 原文写为“打前直拳”的过程及结束阶段，需核对 |
| 前手摆拳 | 前手摆拳未与肩部齐平 | 原文写为“打前直拳”的过程及结束阶段，需核对 |
| 后手摆拳 | 前手向下掉手、向上抬肘、未回收 | 出拳过程及结束阶段 |
| 后手摆拳 | 后手向下掉手、向后拉手、向上抬肘 | 出拳过程及结束阶段 |
| 后手摆拳 | 后手摆拳未与肩部齐平 | 原文写为“打后直拳”的结束阶段，需核对 |

摆拳动作标准中要求“抬肘”，错误项中又包含“向上抬肘”，两者的阶段、幅度和适用手臂需要进一步区分。

## 4. 展示与交互需求

| 项目 | 甲方已填写的内容 | 边界或备注 |
| --- | --- | --- |
| 问题字段 | 问题名称、左右侧或身体部位、问题出现阶段 | 是否同时显示评分依据存在填写冲突 |
| 展示形式 | 文字列表即可 | 不需要回看定位 |
| 画面标注 | 不需要 | 补充填写“第一版不需要” |
| 展示数量 | 显示全部问题 | 未填写数量上限 |
| 排序 | 动作发生顺序、按身体部位 | 两项均勾选，主次未明确 |
| 重复问题 | “不用次数” | 是否合并同类问题未明确 |
| 改进建议及分角色内容 | 填写“第一版不需要回答” | 不作为已确认首期交付项 |
| 查看位置 | 教师端 | 学生直接查看的入口未明确 |
| 结果出现时机 | 未填写 | 尚未确定何时触发分析、何时展示 |

## 5. 异常处理与人工操作

- 视频看不清、遮挡或证据不足：提示重新录制。
- 系统与教师判断不一致：教师可以确认或撤销一条问题。
- 部分项目无法判断时如何处理总分：未填写。
- 未发现任何问题时显示什么：未填写。
- 是否记录修改前后内容、修改人和原因：未填写。

教师确认或撤销功能在第19题中已勾选，但第24题首期交付清单未勾选“人工复核”，因此首期是否交付该功能需统一。

## 6. 保存、导出与历史记录

| 项目 | 已填写要求 |
| --- | --- |
| 结果保存 | 保存到个人历史成绩 |
| 导出形式 | 文字报告 |
| 导出内容 | 扣分点，即动作问题说明 |
| 查看或导出人员 | 学生、老师 |
| 视频和结果保存期限 | 两周 |
| 旧成绩补充分析 | 需要，仅针对仍保留原视频的记录 |

历史记录补充分析的触发方式、处理范围，以及保存期限的起算方式均未填写。

## 7. 首期交付优先级与甲方资料

甲方填写的交付顺序：

1. 文字指出问题。
2. 结果导出。
3. 第三项未填写。

第24题中“结果导出”复选框未勾选，但排序处明确填写，且第20题已勾选导出文字报告，因此有明确的文字导出需求。

甲方确认可以提供评分标准或扣分表。合格视频、错误视频、临界视频、无法判断的视频及教师标注均未勾选，不能视为已经承诺提供。资料提供人、最终确认人、提供时间及期望交付时间均未填写。

## 8. 需要统一的填写冲突

| 事项 | 当前填写情况 | 尚需确定的结论 |
| --- | --- | --- |
| 说明深度 | 第2题为单选，却同时勾选“指出问题”和“指出问题并说明评分要求”；后续未勾选判定依据 | 首期是否展示对应评分要求或依据 |
| 学生与教师入口 | 主要使用者为学生，展示位置仅勾选教师端；学生和教师均可查看、导出 | 学生通过什么入口访问结果 |
| 人工复核 | 第19题勾选教师确认或撤销，第24题未勾选人工复核 | 是否列入首期交付 |
| 误报与漏报 | 第22题为单选，却同时勾选优先减少误报、优先减少漏报 | 两者优先级及分别可接受的范围 |
| 排序方式 | 同时勾选动作顺序与身体部位 | 排序层级或分组方式 |
| 摆拳错误边界 | 标准要求抬肘，错误项也写向上抬肘 | 区分正确抬肘与错误抬肘的具体条件 |
| 规则文字 | 存在“后手保持不同”、摆拳阶段写成直拳、后低鞭腿描述写成“前后鞭腿”等表述 | 由指定教师核对并确认原意 |

## 9. 尚未明确的规则与验收条件

以下内容为空白或尚不足以形成可执行约定：

- 标准文件名称、版本、最终确认人，以及标准存在分歧时的裁定方式。
- 左式、右式及允许动作风格差异的处理方式。
- 组合动作的具体顺序、次数，以及漏做、顺序错误、次数不足是否提示。
- 各问题的允许偏差、错误边界、持续时间，以及临界但合格的表现。
- 同类问题连续出现、反复出现及多视角重复发现时的合并方式。
- 第一版问题说明与现有最终得分的关系。
- 分析触发时机、视频典型时长、允许等待时间。
- 无法判断及未发现问题时的结果展示方式。
- 验收的识别率、误报率、允许无法判断的范围、重复分析一致性。
- 验收视频的提供人、动作和错误样本数量、最终裁定人。
- 完整的真实输出样例及其验收通过条件。
- 期望交付时间。

逐项分值、扣分累计、扣分上限和完整成绩推导等栏目均未填写；结合“第一版不打分”，目前不将其作为首期扣分计算需求。

## 10. 当前可归纳的需求范围

首期围绕实战式、前后手直拳、前后手摆拳、前后低鞭腿，按教师确认的标准识别动作问题，以文字列出问题名称、身体部位和发生阶段，支持历史保存、文字导出，并对仍保留原视频的历史记录补充分析。画面标注和视频回看定位明确不需要。

具体规则边界、教师复核是否纳入首期、评分依据是否展示、学生访问入口，以及量化验收条件尚未确定。本汇总可作为需求讨论依据，不能替代双方确认的最终开发范围与验收标准。
