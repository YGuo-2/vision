# 学生练习动作问题说明实施记录

日期：2026-09-18。按用户选择接入旧版 `apps/app_ui.py` 的“学生练习”。按用户明确纠正，评判仅使用现有 MediaPipe 关键点及几何/时序规则，不使用 Qwen、视觉语言大模型、本机 HTTP 服务或 GPU。正式评分、考试台账和旧默认链路不变。

## 使用

启动旧版桌面，进入“学生练习…”，填写学号、选填姓名，选择动作和左式/右式。选择双摄后点击“开始”，进入正面预览的黄色站位框站稳0.8秒，系统播报“开始”并自动录制；离开该区域连续2秒后播报“结束”并停止录制。短暂离开后回到区域内会重置2秒计时，也可手动点击“结束”（尚未到位时取消等待）。等待转码落盘后点击“动作评判”；再次练习需重新点击“开始”。学生、动作和左右式在开录时绑定，等待到位期间锁定填写项。

2026-09-19新增：复用考试模式的MediaPipe Lite站位检测、`PresenceGate`与异步语音播报，按正面画面髋部中点判定是否进入区域。站位框沿用考试模式保存的ROI，没有配置时使用默认区域；需要更改位置时，先在教师界面的“考试模式…”中设置并保存ROI，再进入学生练习。练习的离场阈值固定为2秒，不叠加考试的最短录制3秒限制。语音不可用时仍显示文字提示。

支持实战式、前后手直拳组合、前后手摆拳组合、前/后低鞭腿；也可选单独前后手拳法。通过“导入旧视频”选择同一次同步录制的正面/侧面原视频，补充历史分析。单视角只保留观测，不能产生联合结论；缺视角明确标为无法判断，不会把剩余视角升为100%权重。禁止将同一个文件同时作为正侧面输入。

“个人历史”按学号显示结果，支持UTF-8文字导出、重新分析、查看证据帧以及教师确认/撤销。分析模型默认Full，可选Lite/Heavy；选择后重分析同一条历史可比较模型，预览到位检测仍用Lite。撤销项留存但不进入报告的当前问题清单；复核保存教师姓名、前后状态、原因和时间。重分析保留旧版结果与复核，新结果重新等待复核。本机教师署名不是账号鉴权。

## 实际推理链路

`apps/app_ui.py` → `apps/feedback_panel.py` → `core/feedback_history.py` → `core/action_feedback.py` → `core/feedback_geometry.py` → 现有 `MediaPipePipeline`。

- 单个所选MediaPipe Pose模型、显式 CPU delegate、VIDEO 跟踪模式、关闭手部检测。默认Full，正侧视频串行处理，每路结束释放模型，不常驻大模型服务。
- v4默认原录像帧率逐帧处理（`sample_fps=0`），最长边1920；1080P不再先缩成640像素。此处是送入MediaPipe的画面尺寸，模型内部仍有自身预处理尺寸。顺序解码，只留关键点，不缓存完整视频帧。
- 复用 `derive_valid_mask`、原规则引擎的角度函数、屈膝和脚尖方向检查。不改它们的正式评分行为。
- 丢失帧全部标为无效，不能沿用上一帧姿态。x/z按画面宽高比校正到同一尺度后算几何量，避免非正方形视频角度失真。
- 在录像内部搜索持续稳定护位，避开入场/离场，不固定使用文件头尾。以指定肢体相对躯干的离开和回收检测阶段，最大位移附近作为动作结束瞬间；保留多轮完整且顺序明确的前后组合，不机械平分录像。当前不自动识别拳法类别，动作类型由用户选择；重叠、错序或不完整组合保留无法判断。
- 每路先按有效帧占比、问题帧占比形成观测，再按下述动作/检查项权重融合；缺有效关键点/视角/对应阶段不判为合格。翻胯/甩手等“未做”检查要求在整个被检阶段均未观察到该动作，不能因起始帧尚未完成就报错。
- `FeedbackConfig` 保留采样、阶段检测和几何容差标定入口；结果保存所用配置。工程阈值尚未经指定教师样本验收，因此 `calibrationStatus=unvalidated`、`scoreAuthorized=false`，不输出总分或扣分。
- 取消在逐帧推理前及保存前检查，不再等待HTTP请求。缺少所选模型时明确提示通过既有“设置→模型管理”安装，不在分析过程中静默下载；交付EXE内置三个Pose模型及手部模型。

## 2026-09-20：双视角加权

本版处理同次双摄录像，按同一动作的同一阶段联合判断；不把一个含转身的视频自动拆成两路，也不把不同时刻的两次演示当成同步双摄。v4的阶段共享条件见下一节。每阶段起止时间相差超过0.4秒时，不融合，提示检查配对。该门限可配置，并不意味着已实现相机时钟标定或逐帧三维重建。

以下正面/侧面基础权重是**未标定的工程初值**，不能当作专业动作准确率或正式评分标准。组合动作分别按前手/后手所在动作类别计算，开始与结束实战式均使用实战式配置。

| 动作或检查项 | 正面/侧面 |
| --- | --- |
| 实战式默认 | 50% / 50% |
| 实战式前手肘角、双膝微屈 | 20% / 80% |
| 实战式后手护位 | 60% / 40% |
| 直拳默认 | 40% / 60% |
| 直拳掉手、抬肘、拳肩齐平 | 70% / 30% |
| 摆拳默认、拳肩齐平 | 60% / 40% |
| 摆拳掉手、抬肘 | 75% / 25%、70% / 30% |
| 低鞭腿默认 | 40% / 60% |
| 低鞭腿掉手、抬肘 | 65% / 35% |
| 低鞭腿脚背、翻胯、甩手 | 15% / 85%、70% / 30%、60% / 40% |

- 实际权重 = 基础权重 × 该检查项有效帧比例，再在有效的两路之间归一化。每路至少3个有效采样帧，且有效比例至少60%；不满足时保留证据，不生成联合结论。
- 每路的“发现问题”记为1，“未发现”记为0，加权得到**问题支持度**。默认达到70%才列为候选问题，不超过30%列为“已检查帧中未发现”，中间区间留给教师复核。支持度不是动作成绩，也不是概率或置信度。
- 旧公式中的“向后拉手”仅适用侧面，“脚尖方向”和“躯干朝向”仅适用正面。这三项明确记录 `primary_view`，另一视角仅核对对应阶段，不参与公式计算，报告注明其限制。不会假造第二路几何证据；规则待确认项仍保持待确认。
- 结果保存基础权重、实际权重、两路有效帧/问题帧比例、支持度及支持/反对问题的证据帧。个人历史点击具体检查项可查看；文字报告区分候选问题、证据不足、规则待确认及已检查未发现问题。
- 缺视角或阶段失败不会因为加权而自动修复。v4允许完整重复组合及短暂漏点，仍不对二维投影误差作准确率保证。

权重在 `core/feedback_geometry.py` 的 `FeedbackConfig` 中定义。可在源码仓库根或离线版 `%LOCALAPPDATA%\VisionSanda` 创建 `feedback_config.json`，下一次分析读取，旧历史不变。只调整阈值可写 `{"fusion_support": 0.75}`；修改权重时需要提供完整四类 `front_weights`，数值代表正面权重，侧面为1减该值：

```json
{
  "front_weights": {
    "stance": {"default": 0.5, "stance_elbow": 0.2, "stance_knee": 0.2, "stance_rear_guard": 0.6},
    "straight": {"default": 0.4, "guard_low": 0.7, "guard_elbow": 0.7, "shoulder_level": 0.7},
    "hook": {"default": 0.6, "guard_low": 0.75, "guard_elbow": 0.7, "shoulder_level": 0.6},
    "kick": {"default": 0.4, "guard_low": 0.65, "guard_elbow": 0.65, "foot_flexed": 0.15, "hip_turn": 0.7, "arm_swing": 0.6}
  }
}
```

双视角权重必须大于0且小于1，非法配置明确报错。单视角公式的适用范围不能通过配置改变。实际配置随每次结果保存，重新分析会保留旧版本结果。加权版规则版本为v3，下面的精度优化版为v4。

## 2026-09-20：v4采集、分段与证据优化

用户提供的6、7号文字报告均记录 `sanda-feedback-mediapipe-2026-09-20-v3`：各有25项无法判断、13项规则待确认，25项均卡在“正侧面未同时找到有效的同一动作阶段”。它们未进入加权结论，不能解释为学生25项动作错误。仅凭旧文字报告不能定位具体机位或关键点，本次未获得甲方的原录像。

- 学生练习接管双摄后请求1920×1080；驱动不支持时沿用实际帧尺寸，报告显示录像真实尺寸。录像帧率显示的是文件标称值，不冒充摄像头实测采集帧率。
- 离线默认Full逐帧分析，Lite可用于同段视频的速度/结果对比，Heavy也可选。Full和逐帧会增加分析耗时；本次没有甲方电脑速度或真人准确率数据。
- 肩髋尺度只使用可见的同侧肩髋链，稳定护位至少有一条可见手臂链；可见但移动的手臂仍会使窗口不稳定。每个规则只要求自身用到的点；远侧遮挡不再否定无关的近侧检查。低置信度、越界、非有限坐标仍无效，不降低关键点置信度门限。
- 按秒配置稳定窗口、短漏点容忍和完成窗口，离开/回收使用不同阈值。短漏点不插值、不复用上一帧；长遮挡必须重新观察护位和起手。重复的完整前后手组合分别保留，错序或缺失不强行拼接。
- 两路都有至少两个对应峰值时，估计一个不超过0.4秒的固定偏移；残差超过0.1秒或次数不一致时拒绝融合。没有足够峰值时沿用同步录像时间，不声称已校准时钟。
- 一路没有检测到完整运动、另一路有完整动作，且起始护位时间相符时，可共享另一机位的同步阶段时间。已有局部动作但次数/顺序错误不会被覆盖。测量仍使用本路原始有效点，关键点不足仍无法判断；报告明确时间段来源。共享依赖输入确实为同次同步双摄，不能验证误选的相似录像身份。
- 每条报告增加逐路尺寸、处理帧数、耗时、关键点有效比例、阶段时段及来源、对齐信息；每项保存角度/相对距离的中位数与范围。历史中的“查看证据帧”显示每路最多三张代表原帧与有效关键点，便于现场核对。
- 开始/结束播报的共用Windows进程增加 `CREATE_NO_WINDOW` 和隐藏窗口参数，避免窗口版EXE每次播报弹出控制台。

13项待确认规则仍不因上述优化变成自动合格，包括未标定厘米距离、Pose无法可靠区分的拳形/含胸收腹及有歧义的阶段规则。规则版本为 `sanda-feedback-mediapipe-2026-09-20-v4`；旧记录须在个人历史中重新分析，旧结果保留。

## 规则依据与边界

依据 `docs/扣分点说明功能需求汇总.md` 和 `docs/武术散打得分点.docx`。本次读取的Word表1共18行：开始实战式3～9行、直拳10～11行、结束实战式12～18行；其中没有摆拳或低鞭腿，后两类按需求汇总3.3/3.4节纳入。Word第11行的前手向后拉手补足汇总遗漏。原文2分/15分不进入新模块计算。

| 检查项 | 实现与限制 |
| --- | --- |
| 前手肘角90°～135° | 按左/右式选择实际前手，计算二维肩肘腕夹角；不以任一手合格替代前手。仍有投影误差。 |
| 后手护位、掉手、抬肘、回收 | 手腕/口部/肩肘/躯干的相对距离与高度规则。 |
| 向后拉手 | 侧面视角相对初始护位的位移；前向不明确时无法判断。 |
| 屈膝、脚尖、躯干朝向、肩部齐平 | 关键点角度、方向和相对高度/宽度规则。 |
| 低鞭腿勾脚尖、翻胯、同侧甩手 | 侧面膝踝脚尖夹角、髋轴相对初始姿态转动、手腕下摆位移；髋深度来自MediaPipe估计，非真实三维测量。 |
| ±3 cm、±10 cm | 保留标准和出处；没有长度标定不能换算成真实厘米，标记待测量确认。 |
| 立拳、含胸收腹 | 轻量Pose关键点不可靠覆盖这些细节，标记需教师查看。 |
| 摆拳抬肘与阶段错字、出拳侧护手规则 | 保留条目及原文疑点，未明确阶段边界前不自动报错。 |

按开始、前手、后手、结束及身体部位列出全部问题；同一检查编号不重复计次数。未发现问题不等于所有项目合格，同时显示未完成判断的项目。规则来源与数值依据不等于识别准确率已验收。

## 保存与两周保留

`outputs/practice_feedback/<随机编号>/` 保存视频副本、结果和复核记录，与考试台账分开。学号不参与文件路径。原子替换保存记录，分析未完成不出现在历史列表。

保留期从首次导入/分析起计14天，复核/重分析不续期。访问历史时清理到期的受管副本及结果；程序关闭期间不运行删除服务。外部导入文件、原录制目录中的原文件及用户导出的报告不由本模块删除，原录像的统一到期管理仍需明确所有权。
