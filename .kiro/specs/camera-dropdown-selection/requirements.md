# Requirements Document

## Introduction

本特性改造桌面应用 `apps/app_ui.py` 中 `App` 类的输入源选择交互。当前用户需要在自由文本输入框（`ttk.Entry`，绑定 `self.source_var`，默认值 `"0"`）中手动输入摄像头编号（数字），同一输入框还兼用于输入视频文件路径（通过“选择视频…”按钮填充）。这种方式不直观，用户无法预知系统上有哪些可用摄像头。

本特性引入一个下拉选择菜单，让用户从“当前可调用的摄像头列表”中直观选择摄像头，同时保留对视频文件路径输入的支持。摄像头枚举基于 Windows 平台的 OpenCV DSHOW 后端，可参考仓库中 `outputs/camera_probe.py` 的扫描实现。下拉选择摄像头与选择视频文件两种输入源在改造后必须共存。

## Glossary

- **UI**：`apps/app_ui.py` 中的 `App` 类所实现的 Tkinter 桌面图形界面。
- **摄像头枚举器（Camera_Enumerator）**：负责通过 OpenCV DSHOW 后端探测系统上可成功打开的摄像头并返回其编号列表的组件。
- **摄像头条目（Camera_Entry）**：下拉菜单中代表单个可用摄像头的一项，包含面向用户的显示文本与对应的整数摄像头编号。
- **摄像头编号（Camera_Index）**：传递给 `cv2.VideoCapture(int(index), cv2.CAP_DSHOW)` 的非负整数索引。
- **摄像头下拉菜单（Camera_Dropdown）**：UI 中用于从可用摄像头列表中选择摄像头的下拉控件（`ttk.Combobox`）。
- **输入源（Input_Source）**：传递给采集逻辑 `_worker_loop` 的最终输入标识，可为摄像头编号字符串或视频文件路径字符串。
- **视频文件路径（Video_File_Path）**：用户通过“选择视频…”按钮选定的本地视频文件的文件系统路径。
- **采集逻辑（Capture_Worker）**：`App._worker_loop` 方法，依据输入源打开摄像头或视频文件。
- **扫描上限（Scan_Limit）**：摄像头枚举器探测摄像头编号时的最大编号上界。

## Requirements

### Requirement 1: 枚举可用摄像头

**User Story:** 作为用户，我希望系统自动列出当前可调用的摄像头，以便我无需记忆或猜测摄像头编号。

#### Acceptance Criteria

1. WHEN UI 启动完成，THE 摄像头枚举器 SHALL 从摄像头编号 0 起，按编号递增逐一探测直至达到扫描上限（含上限对应编号），并将每一个判定为可用的摄像头编号按升序加入摄像头条目列表。
2. THE 摄像头枚举器 SHALL 使用 OpenCV DSHOW 后端（`cv2.CAP_DSHOW`）探测每一个摄像头编号。
3. WHEN 探测某摄像头编号，THE 摄像头枚举器 SHALL 在该编号同时满足“已打开”且“能读取到一帧非空画面”两个条件时判定其为可用，否则判定为不可用。
4. IF 某摄像头编号判定为不可用，THEN THE 摄像头枚举器 SHALL 将该编号排除在摄像头条目列表之外。
5. IF 对单个摄像头编号的打开与读取在 2 秒内未完成，THEN THE 摄像头枚举器 SHALL 终止对该编号的探测、将其判定为不可用，并继续探测下一个编号。
6. THE 摄像头枚举器 SHALL 在完成全部编号探测后释放探测过程中打开的所有摄像头资源。
7. THE 摄像头枚举器 SHALL 使用 5 作为默认扫描上限，且扫描上限的可取值范围为 1 至 32（含端点）。
8. IF 完成探测后摄像头条目列表为空，THEN THE 摄像头枚举器 SHALL 返回空列表并向 UI 提供指示“未检测到可用摄像头”的状态。

### Requirement 2: 以下拉菜单选择摄像头

**User Story:** 作为用户，我希望从下拉菜单中选择摄像头，以便直观地切换输入摄像头而不必手动输入数字。

#### Acceptance Criteria

1. THE UI SHALL 以摄像头下拉菜单替代原有用于输入摄像头编号的自由文本输入框，且界面中不再保留该自由文本输入框。
2. THE 摄像头下拉菜单 SHALL 为摄像头条目列表中的每一个摄像头条目显示一项面向用户的非空文本，且该文本与对应整数摄像头编号一一对应。
3. WHEN 用户从摄像头下拉菜单中选择一个摄像头条目，THE UI SHALL 将该摄像头条目对应的整数摄像头编号记录为当前输入源，并在下拉菜单中持续显示该条目的面向用户文本作为当前选中项，直至下一次选择发生。
4. WHILE 摄像头下拉菜单处于展开供选择状态，THE 摄像头下拉菜单 SHALL 仅允许用户从已列出的摄像头条目中选择，且不接受用户输入任意自由文本。
5. WHEN UI 启动完成且摄像头条目列表非空，THE UI SHALL 将摄像头条目列表中的第一项设置为摄像头下拉菜单的初始选中项，并将其对应的整数摄像头编号记录为当前输入源。
6. IF 摄像头条目列表为空，THEN THE UI SHALL 在摄像头下拉菜单区域显示提示文本，告知用户未检测到可用摄像头，并将摄像头下拉菜单设置为不可选择状态，且不记录任何当前输入源。

### Requirement 3: 保留视频文件输入

**User Story:** 作为用户，我希望仍能选择本地视频文件作为输入源，以便对已录制的视频进行离线处理。

#### Acceptance Criteria

1. THE UI SHALL 始终显示一个标注为“选择视频…”的按钮，且该按钮处于可点击状态，供用户选择本地视频文件。
2. WHEN 用户通过“选择视频…”按钮选定一个可成功打开的视频文件，THE UI SHALL 将该视频文件的完整路径记录为当前输入源，并在界面上显示该路径。
3. WHEN 当前输入源为视频文件路径且用户随后从摄像头下拉菜单选择一个摄像头条目，THE UI SHALL 在同一操作内将当前输入源由视频文件路径切换为所选摄像头编号，并清除先前记录的视频文件路径，使任一时刻仅存在一个生效的输入源。
4. WHEN 当前输入源为摄像头编号且用户随后通过“选择视频…”按钮选定一个可成功打开的视频文件，THE UI SHALL 在同一操作内将当前输入源由摄像头编号切换为该视频文件路径，并清除先前记录的摄像头编号，使任一时刻仅存在一个生效的输入源。
5. THE UI SHALL 在界面上显示一个输入源指示，其取值为“摄像头”加摄像头编号或“视频文件”加文件路径两类之一，使用户能够区分当前生效的输入源类型。
6. IF 用户在“选择视频…”对话框中未选定任何文件（取消操作），THEN THE UI SHALL 保持当前输入源不变，且不修改界面上显示的输入源指示。
7. IF 用户选定的视频文件无法被成功打开或读取，THEN THE UI SHALL 拒绝将其设为当前输入源、保持先前输入源不变，并显示指示文件无法打开的错误提示。

### Requirement 4: 将所选输入源传递给采集逻辑

**User Story:** 作为用户，我希望点击“开始”后系统按我所选的输入源采集，以便正确打开摄像头或视频文件。

#### Acceptance Criteria

1. WHEN 用户点击“开始”且当前选中的输入源为摄像头编号（非负整数），THE 采集逻辑 SHALL 以该摄像头编号作为索引调用 `cv2.VideoCapture(摄像头编号, cv2.CAP_DSHOW)` 打开该摄像头，且不使用任何其他索引。
2. WHEN 用户点击“开始”且当前选中的输入源为视频文件路径，THE 采集逻辑 SHALL 以该完整文件路径作为参数打开该视频文件，且不调用 `cv2.CAP_DSHOW` 摄像头打开方式。
3. IF 用户点击“开始”时既未选中任何摄像头条目也未选中任何视频文件，THEN THE UI SHALL 显示一条指明“未选择输入源”的错误提示，且不启动采集逻辑，并保持“开始”按钮可再次点击的可操作状态。
4. IF 采集逻辑在打开当前输入源后经 `VideoCapture.isOpened()` 判定为未成功打开（返回 False），THEN THE UI SHALL 显示一条包含该输入源标识（摄像头编号或视频文件路径）的错误提示，且不进入采集循环，并保持“开始”按钮可再次点击的可操作状态。
5. IF 当前选中的视频文件路径所指向的文件不存在或不可读取，THEN THE UI SHALL 显示一条包含该文件路径的错误提示，且不调用采集逻辑打开该路径。

### Requirement 5: 刷新可用摄像头列表

**User Story:** 作为用户，我希望在插拔摄像头后能够刷新可用摄像头列表，以便选择新接入的摄像头而无需重启应用。

#### Acceptance Criteria

1. THE UI SHALL 提供一个刷新控件，供用户重新枚举可用摄像头。
2. WHEN 用户触发刷新控件，THE 摄像头枚举器 SHALL 在 5 秒内重新执行摄像头探测（探测索引范围 0 至 9），并以探测结果更新摄像头条目列表。
3. WHILE 摄像头枚举器正在执行探测，THE UI SHALL 禁用刷新控件，以避免重复触发探测；并在探测结束后重新启用刷新控件（采集逻辑正在运行的情况除外）。
4. WHEN 摄像头条目列表在刷新后发生变化，THE UI SHALL 以更新后的摄像头条目列表重建摄像头下拉菜单的可选项。
5. IF 刷新后探测到的可用摄像头数量为 0，THEN THE UI SHALL 将摄像头下拉菜单的可选项清空，并显示提示信息表明未检测到可用摄像头。
6. IF 摄像头探测在执行过程中失败或在 5 秒内未完成，THEN THE UI SHALL 保留刷新前的摄像头条目列表与下拉菜单可选项不变，并显示提示信息表明刷新失败。
7. WHILE 采集逻辑正在运行，THE UI SHALL 禁用刷新控件，以避免在采集过程中重新枚举摄像头。
