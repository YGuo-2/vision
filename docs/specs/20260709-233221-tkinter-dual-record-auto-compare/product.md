# 需求规范 (Product Specification)

> **功能名称：** Tkinter 双摄录制后自动比对
> **版本：** v1.0
> **状态：** 审查中
> **作者：** Codex + Repository Maintainer
> **最后更新：** 2026-07-09

---

## 1. 概述

补全 Tkinter 双摄录制与既有 `compare_dual_streams()` 之间的自动后处理链路。每个有效录制片段在显式结束或主会话停止后异步完成双路转码、校验、DTW 比对、主界面回显和 `result.json` 留档，同时允许用户立即开始下一段录制。

---

## 2. Analyze Requirements / 需求分析结论

- **歧义检查：** “后台动作比对”限定为双摄正面/侧面录像使用固定模板执行既有双流 DTW；不指实时在线 matcher、单视频手工比对、规则评分或 Vue/Tauri 分析。
- **冲突检查：** “只保存一份录像”和“默认带骨架”会使离线二次姿态检测失真。最终规则已改为仅双摄提供骨架开关、默认关闭；开启后允许留存带骨架录像，但该片段明确跳过自动比对。
- **遗漏边界：** 显式结束、主停止、writer 失败、worker `finally`、重复收尾、AVI 回退、模板/模型缺失、不可读视频、零帧、关窗取消、晚回调和连续片段结果覆盖均纳入验收。
- **Intake 未决项归类：** 无未决产品选择。旧 v2 模板继续使用属于兼容性约束；不迁移模板、不修改评分参数属于非目标；现场实际分数不设固定及格阈值。
- **并发 / 数据 / 安全风险：** 双路转码和离线 MediaPipe 可能与实时双摄争用 CPU，必须使用单消费者 FIFO 且 `workers=1`；每段按 `segment_id` 去重，`result.json` 同目录原子替换；功能只处理本地视频，不引入网络、身份、权限或敏感数据上传。
- **Quick Plan 跳过原因：** n/a，本工作流使用 strict 模式。

## 3. Intake Handoff / 澄清交接

- **Status:** complete
- **Confirmed facts:** 双摄已能同步录制；`compare_dual_streams()` 及 v2 兼容路径存在；固定正侧模板本机存在但当前被 `.gitignore` 忽略；用户选择每段异步比对、主窗口三项分数、`result.json` 留档。
- **Scope:** Tkinter 双摄录制内容选择、片段统一收尾、转码汇合、后台双流比对、结果回显、结果持久化、取消和资源释放。
- **Non-goals:** 不修改 Vue/Tauri、单摄/离线录像行为、实时在线识别、手工单视频比对、DTW 算法、权重、baseline、规则评分、误差分析、历史列表、自动重试或跨进程恢复。
- **Decision boundaries:** 实现可新增无 Tk 依赖的后处理协调器并重构双摄收尾；固定模板只做交付和校验，不重新标定。
- **Success criteria:** 每个有效双摄原始片段恰好比对一次；连续录制不阻塞且结果不串；成功/失败/跳过/取消均有明确 UI 和原子 JSON；关窗无未取消 ffmpeg、无 Tk 晚回调。
- **Assumptions:** 模板维持 `full + v2`；评分参数固定为 `workers=1`、权重 `0.4/0.6`、baseline `2.0`。
- **Risks:** 后台任务资源竞争、录制收尾重复调度、被忽略模板导致干净克隆不可用、MediaPipe native 资源未释放。

## 4. 用户故事与验收标准

### US-001: 双摄片段自动比对

**作为** 现场测试人员，**我希望** 每段双摄录像结束后自动进行正侧动作比对，**以便** 不离开主界面即可连续录制并获得评分。

#### 验收标准

- **AC-001.1:**
  - **GIVEN** 双摄会话运行、骨架录制关闭且两路已写入有效帧
  - **WHEN** 用户点击“结束录制”
  - **THEN** UI 立即回到可开始下一段的 idle，当前片段仅提交一次后台任务，任务顺序完成双路转码、校验和比对。
- **AC-001.2:**
  - **GIVEN** 用户正在录制有效双摄片段
  - **WHEN** 用户直接点击主“停止”
  - **THEN** 当前片段自动收尾并仅提交一次，既有排队任务不被取消。
- **AC-001.3:**
  - **GIVEN** 两个或更多片段连续结束
  - **WHEN** 前一片段仍在后处理
  - **THEN** 新片段可继续录制，后台严格 FIFO 且最大并发为一，各片段路径和结果不混用。

### US-002: 骨架录像准确性保护

**作为** 现场测试人员，**我希望** 明确选择双摄录像是否写入骨架，**以便** 在自动评分准确性和带标注留存之间作出清晰选择。

#### 验收标准

- **AC-002.1:**
  - **GIVEN** 应用刚启动且未开始双摄会话
  - **WHEN** 查看“双摄录像写入骨架”开关
  - **THEN** 默认关闭；会话运行期间锁定；单摄和离线录像行为不受该开关影响。
- **AC-002.2:**
  - **GIVEN** 骨架开关关闭
  - **WHEN** 双摄录制帧
  - **THEN** writer 接收旋转后的原始帧，预览仍显示标注帧，片段允许自动比对。
- **AC-002.3:**
  - **GIVEN** 骨架开关开启
  - **WHEN** 双摄片段结束
  - **THEN** writer 保存标注帧，片段完成转码后以 `skipped` 留档，UI 明确提示带骨架录像未自动比对且不显示误导分数。

### US-003: 可追溯结果与失败状态

**作为** 现场测试人员，**我希望** 在主窗口看到最近片段状态并在片段目录保留机器可读结果，**以便** 关闭程序后仍可追溯。

#### 验收标准

- **AC-003.1:**
  - **GIVEN** 后台比对成功
  - **WHEN** 任务完成
  - **THEN** 主窗口显示片段、正面分、侧面分和综合百分比，片段目录原子生成完整 `result.json`。
- **AC-003.2:**
  - **GIVEN** 转码回退、模板/模型缺失、文件不可读、writer 失败、帧数不一致或比对异常
  - **WHEN** 后处理执行
  - **THEN** 可读 AVI 回退继续评分并记录 warning；其他失败不调用或不发布部分评分，UI 和 JSON 使用稳定错误码说明原因，后续任务继续执行。
- **AC-003.3:**
  - **GIVEN** 较旧任务在较新片段提交后完成
  - **WHEN** 它发布结果
  - **THEN** 只更新自己的 `result.json`，不得覆盖主窗口当前较新片段状态。

### US-004: 可取消且无资源泄漏的关闭

**作为** 桌面应用用户，**我希望** 关闭应用时后台任务被可靠取消，**以便** 程序不因 ffmpeg 或 MediaPipe 残留而无法退出。

#### 验收标准

- **AC-004.1:**
  - **GIVEN** 存在活动或排队后处理任务
  - **WHEN** 用户关闭应用
  - **THEN** 停止新提交、取消活动任务、清空排队任务、有界等待，并将适用片段标记为 `cancelled`。
- **AC-004.2:**
  - **GIVEN** 转码或特征提取被取消或抛错
  - **WHEN** 清理执行
  - **THEN** ffmpeg 子进程、临时文件、VideoCapture 和 MediaPipe pipeline 均释放，晚回调不得访问已销毁 Tk。

## 5. 非功能性需求

| ID | 类别 | 描述 | 目标指标 |
|:---|:---|:---|:---|
| NFR-001 | 性能 | 后处理不得阻塞 Tk 主线程或录制锁 | `submit()` 立即返回；后台最大并发 1；比对 `workers=1` |
| NFR-002 | 一致性 | 片段任务与结果必须隔离并去重 | 同一 `segment_id` 最多执行一次；JSON 原子替换 |
| NFR-003 | 兼容性 | 保持既有 MediaPipe/模板/录制边界 | v2 模板可用；单摄、离线、Vue/Tauri、评分算法不漂移 |
| NFR-004 | 可用性 | 后台失败不得弹出阻塞式错误或阻止下一段 | 独立状态区显示，worker 继续消费后续任务 |
| NFR-005 | 可退出性 | 关窗必须能取消外部和 native 资源 | 有界等待；无残留非 daemon 工作阻止退出 |

## 6. 约束与假设

### 约束
- 固定模板为 `templates/standard_front_full.npz`、`templates/standard_side_full.npz`，必须随仓库交付。
- `compare_dual_streams()` 保持 `w_front=0.4`、`w_side=0.6`、`baseline=2.0`，规则与误差分析关闭。
- 转码与比对均在录制锁外执行，Tk 更新仅通过 `root.after()` 且带 closing/segment guard。
- 当前脏工作区属于用户，实施不得覆盖无关修改，只操作本规范任务文件。

### 假设
- MediaPipe `pose_full` 模型可通过现有模型管理安装；缺失时自动比对失败但录像保留。
- 摄像头 1 为正面、摄像头 2 为侧面，现场在开始会话前设置正确旋转角度。
- 现场实际动作分数不设置固定通过阈值，只验证链路与结果结构。

## 7. 超出范围 (Out of Scope)

- Vue/Tauri 或 JSON bridge 自动比对。
- 单摄/离线录像内容变更或自动比对。
- 模板迁移至 v3、模板重录或评分参数标定。
- 规则评分、关节误差分析、历史结果列表、自动重试、应用重启后恢复队列。
